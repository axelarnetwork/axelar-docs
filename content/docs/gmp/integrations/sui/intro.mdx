[Sui](https://sui.io/) is connected to Axelar through [Amplifier](/infrastructure#a-cross-chain-protocol-amplifier). Move packages on Sui can exchange messages with every connected chain, and send tokens with the [Interchain Token Service](/its/integrations/sui/intro).

The packages are in [axelar-cgp-sui](https://github.com/axelarnetwork/axelar-cgp-sui).

## Message flow

Sending, in one transaction:

1. Your package calls `prepare_message` on the gateway with its channel, which returns a `MessageTicket`.
1. The transaction pays gas for the ticket to the gas service (`pay_gas`).
1. The transaction passes the ticket to `send_message` on the gateway, which emits a `ContractCall` event.
1. Axelar verifies the event and routes the message to the destination chain.

Receiving:

1. Once, before the first message, you register the call that delivers messages to your package with the relayer discovery (`register_transaction`).
1. Axelar approves the message on the Sui gateway.
1. A relayer takes the message from the gateway as an `ApprovedMessage` (`take_approved_message`) and calls your registered function with it, in the same transaction.
1. Your function consumes the `ApprovedMessage` with your channel (`consume_approved_message`), then runs your code.

## Setup

You need:

- The [Sui CLI](https://docs.sui.io/guides/developer/getting-started/sui-install). This page was tested with version 1.83.
- A testnet address with SUI: `sui client faucet`, or see [Get SUI tokens](https://docs.sui.io/guides/developer/getting-started/get-coins).

Add the Axelar packages to your package's `Move.toml`:

```toml
[dependencies]
axelar_gateway = { git = "https://github.com/axelarnetwork/axelar-cgp-sui.git", subdir = "move/axelar_gateway", rev = "b35227a82f7ca6f941a7e729e1a3b3d48a64b982" }
relayer_discovery = { git = "https://github.com/axelarnetwork/axelar-cgp-sui.git", subdir = "move/relayer_discovery", rev = "b35227a82f7ca6f941a7e729e1a3b3d48a64b982" }
```

If your package pays gas itself, add `gas_service` the same way, with `subdir = "move/gas_service"`. The Sui framework is included automatically.

The manifests at [this commit](https://github.com/axelarnetwork/axelar-cgp-sui/commit/b35227a82f7ca6f941a7e729e1a3b3d48a64b982) record the testnet IDs of the Axelar packages, so your package links to the deployed packages when you publish it. Don't depend on `main`: its manifests have placeholder addresses (`0xa1`, …), and publishing fails.

## Sui concepts

- **Packages and objects.** A package holds code and no state. State lives in objects, which callers pass into each call. An app that sends and receives messages is a package plus a shared object that holds its state.
- **Channels.** Packages have no `msg.sender`. Your app creates a `Channel` object and keeps it, usually inside its shared object. The channel's ID is your app's address: the source address of the messages it sends, and the destination address of the messages it receives. Only code that holds the channel can send or consume messages as that address.
- **Relayer discovery.** A relayer can't know which of your functions to call, or with which objects. You register that call for your channel in the relayer discovery.
- **Hot potatoes.** `MessageTicket` and `ApprovedMessage` can't be stored or dropped, so the transaction that creates one must consume it.
- **Programmable transaction blocks.** A [transaction](https://docs.sui.io/concepts/transactions/prog-txn-blocks) can chain calls to several packages and pass results between them. Sending a message is one: your package returns the ticket, and the next calls pay gas for it and send it.
- **Addresses and amounts.** Sui addresses and object IDs are `0x` followed by 64 lowercase hex characters. SUI has 9 decimals, and amounts are in MIST: 1 SUI is `1000000000`.
