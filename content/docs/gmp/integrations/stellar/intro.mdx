[Stellar](https://stellar.org/) is connected to Axelar through [Amplifier](/infrastructure#a-cross-chain-protocol-amplifier). Soroban contracts on Stellar can exchange messages with every connected chain, and send tokens with the [Interchain Token Service](/its/integrations/stellar/intro).

The contracts are in [axelar-amplifier-stellar](https://github.com/axelarnetwork/axelar-amplifier-stellar), published as Rust crates.

## Message flow

Sending:

1. Your contract pays gas to the gas service (`pay_gas`).
1. Your contract calls `call_contract` on the gateway, which emits a `contract_called` event.
1. Axelar verifies the event and routes the message to the destination chain.

Receiving:

1. Axelar approves the message on the Stellar gateway.
1. A relayer calls `execute` on your contract.
1. `execute` validates the message with the gateway, which marks it executed, then runs your code.

## Setup

You need:

- Rust 1.84 or later, with the `wasm32v1-none` target: `rustup target add wasm32v1-none`.
- The [Stellar CLI](https://developers.stellar.org/docs/tools/cli/install-cli).
- A funded testnet account: `stellar keys generate alice --network testnet --fund`.

Add the crates to your contract's `Cargo.toml`:

```toml
[dependencies]
stellar-axelar-std = { version = "2.0.1", features = ["derive"] }
stellar-axelar-gateway = { version = "2.0.1", features = ["library"] }
stellar-axelar-gas-service = { version = "2.0.1", features = ["library"] }
```

`stellar-axelar-std` re-exports `soroban-sdk` (version 25), so import Soroban types from it rather than adding `soroban-sdk` yourself. If you do add it, use the same major version, or the types won't match. The `library` feature lets you use the gateway and gas service clients without compiling their contracts into yours.

## Stellar concepts

- **Authorization.** Soroban contracts authorize calls with `require_auth()` instead of `msg.sender`. When your contract sends a message, it authorizes as itself (`env.current_contract_address()`), and the user who pays gas authorizes the payment.
- **Addresses.** Contracts are `C…` addresses and accounts `G…` addresses. Messages carry them as strings: your contract receives `source_address` as a string, and you send to `destination_address` as a string in the destination chain's format.
- **Tokens.** XLM and other assets are used through their token contract (Stellar Asset Contract). Amounts are integers in the token's smallest unit: XLM has 7 decimals, so 1 XLM is `10000000`.
- **Storage expiry.** Contract data expires unless its time to live is extended ([state archival](https://developers.stellar.org/docs/learn/fundamentals/contract-development/storage/state-archival)). `contractimpl` from `stellar-axelar-std` extends your contract's instance storage on every call.
